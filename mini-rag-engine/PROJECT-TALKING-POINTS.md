# Mini RAG Engine - Formal Talking Points

These points are suitable for interviews, technical presentations, architecture reviews, and project summaries. Each concise statement can be used directly, while the explanation provides supporting detail for follow-up questions.

| # | Strong first-person statement | How I explain it in a formal setting |
|---:|---|---|
| 1 | **I architected an eight-module Java 21 system that keeps domain logic, AI providers, persistence, document processing, and HTTP delivery independently maintainable.** | I used a Maven multi-module structure with explicit dependency direction. I isolated the domain model, provider contracts, storage contracts, RAG core, OpenAI-compatible provider, SQLite adapter, PDF adapter, and Spring Boot application so that infrastructure decisions do not leak into retrieval logic. |
| 2 | **I implemented the complete two-path RAG lifecycle: offline document indexing and real-time question answering.** | I built an indexing path that validates PDFs, extracts page-level text, creates overlapping chunks, generates embeddings, and commits the document atomically. I built a separate query path that embeds a question, ranks evidence, constructs a controlled prompt, invokes a chat model, and returns citations. |
| 3 | **I developed exact semantic retrieval from first principles by implementing vector validation, cosine similarity, score thresholds, deterministic ranking, and configurable top-k selection in plain Java.** | I deliberately avoided hiding retrieval behind an orchestration framework or vector database. I made the vector mathematics visible and testable, and I handled invalid dimensions, zero vectors, non-finite values, model incompatibility, and deterministic tie-breaking. |
| 4 | **I designed two plug-and-play AI boundaries that let me change chat and embedding providers independently without rewriting the RAG pipeline.** | I defined separate `ChatModel` and `EmbeddingModel` interfaces because generation and semantic representation are different capabilities. I implemented both through OpenAI-compatible HTTP adapters, allowing local Ollama or another compatible endpoint to be selected through base URL, model name, API key, and timeout configuration. |
| 5 | **I created a zero-server persistence layer with three normalized SQLite tables and one atomic document-indexing transaction.** | I stored documents, chunks, and embeddings separately, enforced foreign keys, enabled cascade deletion, and persisted embedding model and vector dimensions beside every vector. I encoded vectors as compact little-endian float32 BLOBs and rolled back the complete indexing operation if any database write failed. |
| 6 | **I preserved evidence provenance from PDF page extraction through the final API response, enabling every retrieved passage to carry a filename, page number, chunk index, rank, and similarity score.** | I extracted each physical PDF page independently before chunking. I kept chunks within a single page so citations remain deterministic, and I returned the underlying retrieval evidence with generated answers so users can inspect why the system answered as it did. |
| 7 | **I strengthened grounded generation by separating trusted instructions from untrusted document evidence and by requiring explicit refusal when retrieval is insufficient.** | I labelled every retrieved passage as untrusted evidence, instructed the model not to follow document-borne instructions, and required source-number citations. I also exposed retrieval through a separate search endpoint because I recognize that prompt controls reduce risk but do not guarantee factual correctness. |
| 8 | **I exposed five focused REST operations for document lifecycle, retrieval inspection, and grounded question answering.** | I implemented PDF upload, document listing, document deletion, semantic search, and RAG question answering. I added request validation, multipart limits, structured JSON errors, configurable retrieval overrides, and a separate health endpoint for operational checks. |
| 9 | **I validated the first vertical slice with nine automated tests plus an executable application smoke test that returned a healthy status and a valid empty document collection.** | I tested cosine mathematics, chunk boundary behavior, SQLite persistence and cascade deletion, and both OpenAI-compatible adapters through a local HTTP stub. I packaged and started the assembled Spring Boot application, verified `/actuator/health` returned `UP`, and confirmed the document endpoint responded correctly. |
| 10 | **I documented the system for both beginners and maintainers with one end-to-end runbook, eight module-specific guides, extensive learning-oriented Javadocs, and step-by-step replacement procedures.** | I documented installation, build, startup, API usage, configuration, troubleshooting, and maintenance rules. I explained how to replace a compatible model through configuration, add a non-compatible provider through an adapter, introduce another document format, or migrate from SQLite to a vector database without destabilizing core logic. |

## Concise executive summary

I built a local-first Mini RAG Engine in Java 21 that demonstrates the mechanics behind enterprise document question answering without depending on LangChain, Oracle infrastructure, or a hosted database. I separated the system into eight maintainable modules, implemented semantic retrieval and SQLite vector persistence directly, exposed five REST operations, and validated the initial vertical slice with nine automated tests and a live application smoke test. I designed the model and storage boundaries for controlled replacement, and I documented the system so a beginner can run it while an experienced engineer can extend it safely.

## Responsible qualification

I describe this project as a tested learning-first vertical slice rather than a production-complete platform. I identify OCR, authentication, large-scale approximate vector indexing, asynchronous ingestion, formal retrieval evaluation, and production observability as deliberate future extensions instead of implying that the current V1 already solves them.
